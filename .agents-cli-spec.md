# Agent Spec: Resume to Job Application Agent System

## Overview
The NextRole.Ai system is built using the Google Agent Development Kit (ADK) framework and integrated with a React web dashboard. It implements a hierarchical multi-agent architecture where a parent Coordinator Agent orchestrates five specialized sub-agents to perform resume parsing, job discovery, security validation, form filling, and ATS optimization.

---

## Hierarchical Multi-Agent Architecture
To prevent overlapping tasks and minimize hallucination, the system is divided into six distinct, non-overlapping roles:

1. **Parent Coordinator Agent** (Workflow Controller & User Dispatcher):
   - Acts as the central orchestrator and dispatcher for user requests.
   - Routes requests to specialized sub-agents and monitors progress.
   - Synchronizes agent execution status (Idle, Running, Completed, Error) with the React frontend through a local SQLite database state.
   - Skills/tools: `route_workflow_step`, `validate_workflow_state`, `request_user_confirmation`, `write_status_update`, `log_audit_event`.

2. **Security Agent** (Gatekeeper & Safety Guardrail):
   - Performs domain whitelisting, limiting browser navigation strictly to approved target domains (`linkedin.com` and `www.linkedin.com`).
   - Checks action inputs to sanitize and prevent code injection or malicious operations.
   - Enforces execution limits (e.g. capping batch runs to between 1 and 20 applications) and ensures candidate PII is omitted from diagnostic logs.
   - Skills/tools: `validate_domain`, `validate_inputs`, `validate_action`.

3. **Resume Agent** (Builder & Parser):
   - Ingests candidate resume files (PDF), extracts raw content, and parses it into structured candidate nodes (Experience, Skills, Education).
   - Evaluates resume keyword density and formatting to generate baseline and projected ATS readiness scores.
   - Exports tailored candidate assets (Cover Letters, Bullet Improvements) after optimization.
   - Skills/tools: `parse_resume_file`, `extract_resume_text`, `score_resume_ats`, `suggest_resume_improvements`, `project_improved_ats_score`, `apply_approved_resume_changes`.

4. **Job Intelligence Agent / Job Alerts Agent** (Job Scout & Match Analyzer):
   - Scrapes job postings daily or on-demand based on target search criteria (keywords, location).
   - Evaluates matching coefficients by comparing description keywords with parsed resume parameters, grading compatibility from $45\%$ to $96\%$.
   - Prepares and sends HTML email summaries of top matching roles via SMTP.
   - Skills/tools: `validate_job_search_criteria`, `search_jobs_with_playwright`, `extract_job_posting_details`, `score_resume_to_job_match`, `extract_missing_skills_and_keywords`, `rank_job_matches`, `prepare_email_alert`, `send_email_with_smtplib`.

5. **Application Agent** (Portal Form Automation):
   - Spawns background worker instances to automate form submissions on external portals like Greenhouse and Lever.
   - Uses selector heuristics to identify input labels, dropdown menus, radio choices, and checkbox controls, pre-filling them using parsed profile data.
   - Pauses before clicking the final submit button (Safety Gate) to ensure user oversight.
   - Skills/tools: `open_application_with_playwright`, `detect_application_platform`, `fill_application_form`, `upload_resume_file`, `submit_or_pause_before_submit`.

6. **LinkedIn Form Filler Agent / Easy Apply Agent** (LinkedIn Automation Specialist):
   - Directs the browser robot through LinkedIn login sequences and dynamic Easy Apply form modals.
   - Detects security checkpoints (OTP/2FA challenge screens) and writes a prompt entry to the SQLite database.
   - Pauses execution and enters a checking loop, resuming immediately when the user enters the OTP code in the React Agent Console.
   - Skills/tools: `login_to_linkedin`, `detect_2fa_checkpoint`, `fill_easy_apply_modal`, `poll_otp_from_sqlite`, `resume_after_2fa`.

## Example Use Cases
### Case 1: Resume Creation & Customization
- **Input**: Candidate details, LinkedIn PDF/text, or target resume example.
- **Process**: The Coordinator routes to the **Resume Agent**, which parses/formats inputs, mimics layouts, and templates the content.
- **Output**: Structured candidate profile and clean HTML/Markdown resume data.

### Case 2: Resume Optimization & Generation
- **Input**: Resume data + Job Description.
- **Process**:
  1. The **Resume Agent** evaluates the alignment, computes the baseline score, and suggests improvements.
  2. With user approval, the **Resume Agent** refines the experience details and generates an optimized PDF/Docx.
- **Output**: Improved ATS scorecard, updated resume.

### Case 3: Email Job Alerts (Daily & On-Demand)
- **Daily Job Search**: The agent uses Playwright and local cookies from `playwright_session/` to search LinkedIn for jobs posted in the last 24 hours matching the candidate's profile, runs match percentage scoring, and emails a structured HTML list via SMTP.
- **On-Demand Search**: The user enters parameters in Streamlit. The agent scrapes matching LinkedIn jobs, identifies missing skills/keywords, ranks the jobs, and emails the list immediately.
- **SMTP Handling**: Preconfigured default/mock details exist for quick setup, with an "Advanced Settings" accordion in Streamlit to use private SMTP credentials.
- **Triggers**:
  - A manual "Trigger Alert" button in Streamlit.
  - A standalone script `daily_job_alerts.py` that can be scheduled via Task Scheduler.

### Case 4: Semi-Automated Form Filling
- **Process**: The **Application Agent** opens the application page, populates inputs, uploads the PDF, pauses for user responses to unknown fields, and halts before the final submission button.

### Case 5: Lower-Match Review & Re-scoring
- **Process**: The **Job Alerts / Job Intelligence Agent** ranks jobs below the threshold, prompts the user to confirm experience with missing skills in Streamlit, collects short experience notes, updates the resume, and re-scoring affected jobs. If a job match rises above the threshold, it is routed to the **Application Agent**.

## Constraints & Safety Rules
- **Gatekeeper Guardrail**: The Coordinator Agent blocks any non-career/off-topic queries immediately.
- **Truthfulness Guardrail**: Agents must strictly stick to existing candidate resume facts. No fabrication of skills, credentials, employment history, education, certifications, or project experience is allowed.
- **Semi-Automated Constraint**: The Application Agent MUST NOT submit the final form. It must pause before the final "Submit" button.
- **Opt-In Requirement**: Automated applications require explicit user opt-in and a user-defined threshold.
- **Audit Logging**: The system must keep an audit log of all resume changes, confirmation points, and application activities.
- **Source Integrity**: Job search results must include source URLs whenever available.
- **Browser Automation Compliance**: Browser automation must respect site terms, authentication requirements, rate limits, and user privacy.
- **Threshold Integrity**: Jobs below the threshold must not be applied to unless re-scoring after user-confirmed resume updates meets the original threshold.
- **Information Disclosure**: ATS scores and match percentages are decision-support signals, not guarantees.
- **Security**: SMTP credentials must not be committed to the repository and must be loaded via local environment variables.

## Testing & Quality Assurance
1. **Pytest Unit Framework** (`tests/unit/`): Validates code correctness of parsers, SMTP emails, log writing, and Playwright element detection.
2. **ADK UAT Eval Framework** (`tests/eval/`): Uses `uat-dataset.jsonl` and `eval_config.yaml` to measure `multi_turn_task_success`, `hallucination`, `safety`, and correct multi-agent delegation.
