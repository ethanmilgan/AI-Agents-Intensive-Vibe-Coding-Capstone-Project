# Agent Spec: Resume to Job Application Agent

## Overview
The Resume to Job Application Agent is a local prototype built using the Google Agent Development Kit (ADK) framework and integrated with a Streamlit interface. It implements a hierarchical multi-agent architecture: a parent Coordinator Agent supervises four specialist subagents to perform resume optimization, matching, auto-filling, and daily notifications.

## Hierarchical Multi-Agent Architecture
To prevent overlapping tasks and minimize hallucination, the system is divided into distinct, non-overlapping roles:

1. **Parent Coordinator Agent** (Entrypoint & Guardrail):
   - Performs LLM Pre-flight Gatekeeper checks to catch and reject off-topic questions.
   - Routes user requests to the correct specialist subagent.
   - Supervises subagent progress and ensures they align with the user's main goal.
2. **ATS Analyzer Agent** (Subagent 1):
   - Computes semantic alignment score (0-100) comparing resume to job descriptions.
   - Identifies skills, keywords, and experience gaps.
   - Provides clear, actionable optimization feedback.
3. **Resume Builder Agent** (Subagent 2):
   - Creates new resumes from manual input, LinkedIn profiles, or template examples.
   - Visual Style Copier: Emulates layout structures (e.g., 2-column sidebar vs 1-column list) and typography choices from PDF/Docx examples, and inherits CSS rules from HTML templates.
   - Tailors resume bullet points to match target job descriptions.
   - Exports finalized resumes to PDF (HTML-to-PDF via Playwright) and Docx (`python-docx`).
4. **Job Alerts Agent** (Subagent 3):
   - Scrapes LinkedIn daily (24 hours) or on-demand using Playwright.
   - Persistent Session State: Uses Playwright's persistent browser context to save LinkedIn session cookies locally in `playwright_session/`, allowing background scraping without daily login prompts.
   - Filters findings using ATS score matching.
   - Emails a stylized HTML job alert list via SMTP.
5. **Form Filler Agent** (Subagent 4):
   - Navigates job applications (Greenhouse, Lever, Workday, LinkedIn Easy Apply).
   - Follows external job search redirects.
   - Automatically fills out form fields and uploads resumes.
   - Pauses Playwright for human-in-the-loop prompts on unknown questions, sends them to the Streamlit UI, paraphrases user inputs, and resumes.
   - Pauses before the final "Submit" button.

## Example Use Cases
### Case 1: Resume Creation & Customization
- **Input**: Candidate details, LinkedIn PDF/text, or target resume example.
- **Process**: The Coordinator routes to the **Resume Builder Agent**, which parses/formats inputs and templates the content.
- **Output**: Clean JSON/Markdown resume data.

### Case 2: Resume Optimization & Generation
- **Input**: Resume data + Job Description.
- **Process**:
  1. The **ATS Analyzer Agent** evaluates alignment and provides a score.
  2. The **Resume Builder Agent** refines bullet points, generates HTML, and compiles PDF/Docx.
- **Output**: Score card, tailored resume PDF/Docx.

### Case 3: Email Job Alerts (Daily & On-Demand)
- **Daily Job Search**: The agent uses Playwright to log in to LinkedIn, search for jobs posted in the last 24 hours matching the candidate's resume/skills, filters them using the ATS matching engine, and emails a structured list of relevant jobs to the user using SMTP.
- **On-Demand Search**: The user enters specific target roles and location in Streamlit, along with their recipient email address. The agent scrapes matching LinkedIn jobs, filters them, and sends a summary email immediately.
- **Under the Hood (Simplification)**: To keep the app layman-friendly, the SMTP sender details (host, port, username, password) are prefilled/mocked in the background (using a dummy account or pre-configured settings). An "Advanced Settings" accordion is provided in the UI for users who want to override and use their own Gmail/SMTP credentials.
- **Triggers**:
  - A manual "Trigger Alert" button in Streamlit.
  - A standalone script `daily_job_alerts.py` that can be scheduled via Windows Task Scheduler or cron.

### Case 4: Semi-Automated Form Filling
- **Process**: The **Form Filler Agent** opens the application page, populates inputs, uploads the PDF, pauses for user responses to unknown fields, and halts before the final submission button.

## Constraints & Safety Rules
- **Gatekeeper Guardrail**: The Coordinator blocks any non-career queries immediately.
- **Truthfulness Guardrail**: Agents must strictly stick to existing candidate resume facts. No fabrication allowed.
- **Semi-Automated Constraint**: The Form Filler Agent MUST NOT submit the final form.

## Testing & Quality Assurance
1. **Pytest Unit Framework** (`tests/unit/`): Validates code correctness of parsers, SMTP emails, log writing, and Playwright element detection.
2. **ADK UAT Eval Framework** (`tests/eval/`): Uses `uat-dataset.jsonl` and `eval_config.yaml` to measure `multi_turn_task_success`, `hallucination`, `safety`, and correct multi-agent delegation.
